# Repository guide

## Layout

```
editor/runtime/lua/editor/     the editor (Lua 5.0, Moho LuaPlus): map.lua (document), tools.lua, ui.lua, gui/ (shell, dock, panels_*.lua, feature_*.lua, widgets.lua) ...
editor/runtime/schook/         files appended to the game's own Lua files (hooks; one chunk with the base file: wrap in do ... end, no top-level local)
editor/runtime/override/       shaders that shadow FAF's (generated by editor/tools/gen_*_fx.py from FAF's files)
engine/faf-re/                 the native side: git submodule of UnsilentMarLo/faf-re (the reconstructed engine plus the editor, branch `editor`); engine/run/ (git-ignored) is the staged engine
.runs/                         (git-ignored) test instances: one folder per tag, with its own log, user data and command channel
scripts/                       tools; scripts/studio_paths.py is the one place that knows where things live (environment variables override)
docs/projects/editor/          design documents, QA reports, packaging / release / branding docs
```

## Daily work

1. `python scripts/editor_inst.py new <tag>` and `start <tag>` run the Lua tree of the current checkout in its own process. `cmd <tag> file.lua` runs a Lua chunk in the editor
   (UI state) and prints the result, `shot <tag> out.png` takes a screenshot. Modules are cached per process: restart the instance after a Lua edit.
2. Add a panel as `gui/panels_<name>.lua` (self-registering, auto-imported). Every number setting is a `W.Slider` (bar, field, minus / plus), never a bare text field.
   Every button and field needs a tooltip (`tipdata.lua`): the nightly's `tips` step fails otherwise.
3. Lay buttons out with `W.Flow` (rows that wrap at the panel's width). A button or label whose text is wider than it is cut with "..." (`W.Fit`; `nofit = true` opts out), a label that is a direct
   child of a panel is cut to the panel's width, a panel that needs more width than it has scrolls sideways (the fallback, not a design: declare `minW` in `Panels.Register`, the dock keeps the stack
   that wide). Dialogs (`gui/dialog.lua`) are clamped to the window and scroll; use `d:Flow`, `d:Text`, `d:Span`, `d:Room` instead of fixed x positions. The nightly's `layout` step
   (`layoutcheck.lua`: all controls and texts, panels, dialogs, 1920x1080 and 1280x720 at UI 100 / 150 / 200 %, a smaller dock area, the narrowest docks) fails when a widget runs past the area the
   user sees or overlaps another.
4. `python scripts/studio.py check` before every commit; `python scripts/editor_nightly.py --tag <own tag> --skip stress` for a thorough run.

## Parallel feature branches

`python scripts/editor_merge.py new <name>` makes a worktree `.claude/worktrees/ed-<name>` on branch `ed/<name>`; `try <name> --test` merges it into an integration tree and runs the
checks, `land <name> --base main --test` merges it. Conventions that keep merges clean: new panels in their own files, sim callbacks in `lua/editorsim/*.lua`, append-only docs merge as
union (`.gitattributes`). Details: `docs/EDITOR_PARALLEL.md`.

## Engine changes

The engine is a git submodule (`engine/faf-re`, our fork `UnsilentMarLo/faf-re`, branch `editor`). The native editor code is `engine/faf-re/src/moho/editor/`, built into the engine with
`-DFAF_EDITOR=ON` (`src/CMakeLists.txt`, `src/moho/editor/editor_sources.cmake`: add a new `Ed*.cpp` there). Work in that checkout like in any git repository: commit on `editor`, `git push origin editor`,
then commit the new pin here (`git add engine/faf-re`). To take a new version of the reconstruction: `git fetch upstream` in the engine and `git merge upstream/master` into `editor` (our changes to
engine files are few: `git diff upstream/master --stat` lists them), build, test, push.

`python scripts/studio.py build` is the one command that brings the engine to the pinned commit, builds it, builds `edtext.dll`, stages it and prints the timestamps of what it staged. `engine build` alone does
the engine part (CMake + clang-cl; Visual Studio 2022 / 2026 with the C++ tools, LLVM, the June 2010 DirectX SDK). Never commit an exe.

## Packaging and release

`python scripts/package_editor.py` writes `dist/FAFStudio/` and a zip (the version is `editor/VERSION`, `major.minor.patch`, started at 0.5.0: every successful `python scripts/studio.py build` raises the patch number before it stages and brands the exe, `build --no-bump` keeps it, `studio.py version --bump minor|major` / `--set X.Y.Z` change it; build date and git revision are stamped in). `docs/projects/editor/PACKAGING.md`
describes the package, `RELEASE.md` the map release flow, `BRANDING.md` the name, icon and title bar. FFmpeg is compiled into the exe (LGPL): a distribution has to
carry its license texts and source offer. Whether and where to publish a built exe is the owner's decision.

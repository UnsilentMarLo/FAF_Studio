# FAF Studio: QA pass, 2026-10-18

Branch `ed/qa` (worktree `.claude/worktrees/ed-qa`, instance tag `qa`). Method: the editor was driven with posted mouse messages and real
keyboard input (Ctrl+Z / Y / C / V / O, Delete, F5, Ctrl+Shift+P) on a 1280x720 window, with Lua reads of the state after each step
(heights, history depth, marker / decal / prop counts, checksums) and screenshots of every panel. Covered: the Terrain, Objects, Environment,
Mission, Mod and Review workspaces; the brushes (raise, lower, flatten, smooth, plateau, erode, noise, paint layer, erase layer, terrain type, ramp,
ruler, camera); symmetry; terrain generate + undo; markers, areas, props, decals, units (place, select, gizmo, copy / paste, delete, undo / redo);
the Armies, Stages, Unit lab, Unit viewer, Effects, Icons and Mesh terrain panels; File > Open of a real FAF map (`adaptive_acid_lakes`, 5726 props,
1837 decals, 62 markers), save as + reopen (identical checksum and counts), play test (F5) and Stop.

## Follow-up in branch `ed/scroll` (2026-10-18)

| Item | Result |
|---|---|
| Panels do not scroll | Every docked panel now builds in a **content group** (`W.ScrollContent`, made by the dock) that is shifted up by the scroll offset. `W.Place` / `W.Label` give the direct children of that group a lazy rule: a control that does not lie completely inside the panel is moved off screen (Maui has no clipping, so only whole controls are drawn). The content height is the lowest edge placed; when it exceeds the panel (by more than 10 px) the mouse wheel scrolls and an 8 px overlay bar appears on the right edge (drag the thumb, click the track to page). The offset is kept per panel id (`W.scrollMemory`; reset on a UI scale change). A `VirtualList` that has nothing to scroll passes the wheel on to the panel; compound widgets (`Slider`) wrap their parts in `W.CullBox` so they appear and disappear together; a panel that rebuilds its controls (Properties) brackets the rebuild with `W.BeginLayout` / `W.EndLayout`. `W.SetClip` is gone. Checked with real input at UI 100 % and 150 %: Tools (Undo / Redo / Save / Play test / Mods reachable), Brush, Layers, View, Symmetry, Water look (Sun R / G / B), Stages, Properties (Delete), Icons. `selftest_qa` pins the offsets, culling, clamping, rebuild and slider behaviour. |
| Props placed with the prop brush render as grey specks | Not a mesh problem: the sim callback `EdSpawnProp` oriented the prop with `EulerToQuaternion(heading, 0, 0)`, and the **first** argument is the roll, so every prop with a heading other than 0 (the brush's random heading) lay on its side, half in the ground. Now `Quaternion(0, sin(h/2), 0, cos(h/2))`, the same quaternion the map record keeps. Verified in the editor: brush-placed cars stand upright at random yaw. (`markervis.lua` uses `EulerToQuaternion(0, 0, yaw)` for its marker meshes: that rotates about the third axis, not up. Not changed here; worth a look if a marker mesh ever looks tilted.) |
| No box select for units, props, decals | `Tools.BeginBoxSelect` is the shared marquee; `Units.SelectBox`, `Props.SelectBox`, `Decals.SelectBox` take a world rectangle (Shift adds). A drag that starts on empty ground (outside the pick radius of an object) draws the box; a plain click still clears. Real input: 5 props, 5 units, a decal and its normals decal selected by drags; `selftest_qa` checks `Props.SelectBox`. |
| Ctrl+Shift+Z does not redo | `edit.redo` has the second binding `Ctrl+Shift+Z` (slot 2, rebindable in Hotkeys). Engine modifiers come from the real keyboard, so only the key table was checked, not a posted key. |
| Selftests leave fixtures in the document | `editor_inst selftests <tag>` restarts the instance afterwards (same map and exe); `--keep` skips that. `editor_merge --test` uses `--keep` on its throw-away instance. |
| `meshmap` / `unitview` panels logged a resize error | `panels_mesh.lua` formatted a boolean setting with `%d`; `panels_unitview.lua` read the module global `LODInfo` before any LOD was shown. Both fixed (log is clean after cycling every panel of every workspace at 150 %). |

## Test notes

- Posted mouse messages need a preceding mouse move before a click, otherwise the click uses the previous hover (Pick runs on the hover state). A
  real user always moves first.
- The editor window idles when it is not the foreground window; a Lua command through the command channel only runs after a foreground. The helper
  used here calls `SwitchToThisWindow` every 3 s while it waits (`editor_inst focus` clicks the title bar at a screen position that another
  window may cover).

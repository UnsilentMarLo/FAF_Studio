## 1. What exists and what limits us

| Have | Where |
|---|---|
| Brushes: raise, lower, flatten, smooth, plateau, erode (thermal, 3 passes per dab), noise, ramp, ruler, symmetry | `terrain.lua`, `brushes.lua`, `ramp.lua` |
| A whole-map generator: value noise fbm / ridged / billow, island falloff (Lua) | `terraingen.lua` (141 lines) |
| Strata masks (9 layers) with read / write natives, slope based layer painting, terrain type grid from the layers | `strata.lua`, `EdStrata.cpp`, `terraintype.lua` |
| Heightmap import / export (PNG16), height read / write by rectangle (16-bit words, 1/128 unit steps) | `heightio.lua`, `EditorLua.cpp` |
| A native slope overlay (the engine's own slope rule, 0.75 limit for land units) | `EdOverlay.cpp` |
| Undo for terrain strokes (one entry per stroke, exact by checksum), symmetry points | `terrain.lua`, `history.lua`, `symmetry.lua` |

Hard limits that decide the architecture:
1. **Lua is far too slow and heavy for this.** A 1025 x 1025 map is 1.05 M samples (a 20 km map, the largest the editor opens). One hydraulic erosion run is hundreds of iterations over the whole grid: 10^8 - 10^9
   cell updates. Moho LuaPlus does a few 10^7 simple operations per second and a Lua table of 1 M numbers costs ~16 MB and seconds to build. Anything that loops over the map in Lua stays at toy scale
   (the current generator already takes noticeable time at 513).
2. **Heights are 16-bit words** (1/128 world unit). Work in float32, quantise once at the end; masks are 8-bit (strata) at half the height resolution.
3. **Determinism and undo**: a generator run is one undo step (the whole height field, 2 MB at 1025, plus touched masks); results must not depend on the number of threads (fixed tile decomposition, seeded RNG).
4. **Native builds are serial** (`build_deploy.ps1` stops every instance): the native part should be built early, then the Lua / UI work parallelises.

## 2. Recommendation: one native field engine, three front ends

```
          +-------------------------------+
 Lua  --> |  Graph model (nodes, wires)   |--+
 UI       |  Spline objects (paths)       |  |  evaluate(graph) / apply(op)
          |  Brush strokes (local ops)    |--+
          +-------------------------------+  |
                                             v
 native   Field engine (EdField*.cpp): float32 grids held in native memory, referenced from Lua by opaque handles,
          ~100 ops (noise, filters, masks, erosion, curves, warps, combiners), multi-threaded by tiles, deterministic
                                             |
                                             v   one undo entry
          height words / strata masks / terrain types / props / decals / water in the map document
```

The point: **Lua never sees a grid**. It builds an op list or graph, the engine evaluates it in C++ on handles, and only the result (or a down-sampled preview) crosses back. That gives interactive speed
(preview at 1/4 resolution in tens of ms, full resolution in seconds), the same op set for the graph, the spline tool, the mask generator and the brushes, and testability (golden checksums per op).

Three front ends on the one engine:

- **A. Terrain graph** (Gaea / World Machine style): nodes with typed ports (height, mask, color-ramp, points), a canvas with pan / zoom, per-node thumbnail, inspector with sliders, seeds, presets, variation gallery,
  live preview applied to the editing terrain with a revert, "Build" writes it as one undo step. Graphs are files (Lua tables) stored with the map (`_editor.lua` sidecar) and in a preset library.
- **B. Splines and curves**: path objects (Bezier / Catmull-Rom with handles and per-point width, height, bank) drawn in the viewport with the gizmo, plus a **cross-section profile curve** editor. Modes: ramp, road,
  river (carve + water + flow mask + beach strata), canyon, ridge, wall, plateau strip, shoreline, scatter along path. Paths stay editable (non-destructive): re-apply replaces the previous result of that path (kept in
  the undo history), "bake" freezes it.
- **C. Local brushes**: the erode brush becomes a real **local erosion**: N iterations of the same hydraulic / thermal kernels on the brush window (+ 1 cell border), strength = iterations, live while painting
  (a 64 x 64 window is a few ms). More brushes from the same kernels: rain, river source, sediment deposit, terrace, slump, snow / debris drift, stamp (height pattern), clone, "match to curve".

## 3. Field engine

- **Field** = float32 grid with size, origin (map sample or half-resolution mask grid), and a name. Handles created by `ed_field_*` natives, freed by the document / graph. Resample with bilinear / bicubic.
- **Execution**: ops are pure functions of input fields + params + seed; tiles of 64 x 64 + halo, work items on a fixed pool, reduction order fixed -> bit exact across thread counts. Erosion uses double buffering per
  iteration (grid methods) or per-droplet streams with fixed seeds per tile (particle methods).
- **API sketch**: `f = ed_field_height()`, `ed_field_op('slope', {src = f, ...}) -> g`, `ed_field_graph(text) -> handles`, `ed_field_preview(f, size) -> small table`, `ed_field_commit_height(f)` / `commit_mask(f, layer)`,
  `ed_field_stats(f)`, `ed_field_free(f)`. Graph evaluation caches per node by a hash of (params, inputs) so changing one node re-runs only downstream.
- **Resolution policy**: full resolution for results, 1/4 for interactive preview (same op, `scale` aware so features keep their world size), tiling for maps > 1025 when they arrive.

## 4. Node catalogue (P1 first, P2 next, P3 later)

**Generators** P1: Perlin / simplex fBm, ridged, billow, Voronoi (cells, edges, distance), gradient (linear, radial), constant, slope-ramp, hills, mountains (ridge + erosion preset), dunes P2, cracks P2,
terraces P2, craters P2, island P2, image import (PNG16 / RAW) P1, shape (circle, rect, polygon from path) P1.
**Filters / shaping** P1: blur (gauss, box, directional), sharpen, clamp, invert, remap (curve editor, like Photoshop curves), levels, terrace, slope-limit (clamp max gradient: guarantees pathable slopes), smooth
(preserving ridges, bilateral) P2, warp (by noise or by a field) P1, offset / rotate / scale / mirror / tile P1, min / max / add / mul / subtract / blend modes / mask blend P1, expand / shrink / distance field P1,
quantize to word grid P1, edge detect P2, morphology (open, close) P2, convolution kernel P3.
**Erosion** (the Gaea core): thermal / talus P1; **hydraulic grid (pipe / shallow water model with sediment capacity, evaporation)** P1; droplet particle erosion P1; stream-power / incision with flow accumulation
(river networks) P2; sediment deposition and **wear / flow / deposit / flow-accumulation outputs as masks** P1 (they texture the terrain); rockiness / rock-soil split P2; glacier / snow-slump P3; wind P3.
**Analysis → masks** P1: slope (degrees, and *unit class*: land / hover / amphibious per the engine rule), height band (min / max with soft edges), curvature (convex / concave), aspect / angle (facing the sun: lets
snow or moss sit on shaded sides), water: below / above level, depth, shoreline / beach band, flow accumulation, cavity / occlusion (ambient), distance to marker / path / base pad, noise, position (x / z gradients),
combinators (and / or / not / difference / multiply, "subtract the layers above": the strata cascade), threshold / smoothstep, blur, grow / shrink.
**Outputs** P1: height (with water level / playable area / edge falloff), strata layer n (with the usual "layers above take away" logic), terrain type grid (mask → type, uses the existing defaults per texture), props scatter (blueprint list + density
mask + slope / height limits + min distance, Poisson disc, seeded, one undo step) P1, decals scatter P2, markers (mass / hydro points on flat spots, validated against the build grid) P2, preview picture / minimap P1.

## 5. Features only a Supreme Commander editor can offer (differentiators)

1. **Buildability and pathing aware shaping**: `slope-limit` and the slope masks use the engine's own rule (0.75 over a unit footprint window); a graph can guarantee "this ramp is pathable for land units".
2. **Pads and rings**: nodes `base pad` (flatten a start position / mass point cluster to the build grid with a smooth skirt) and `resource ring` driven by the markers; re-evaluate when markers move.
3. **Symmetry as a first class op**: mirror / rotate N-fold applied to the *graph result* (not the dabs), seed compatible, so a competitive map is symmetric by construction; marker symmetry already exists.
4. **Map skeleton generator**: from start positions and a lane style (open, ridge lanes, ramps / chokes, islands) it lays down spline paths and base pads; the user edits the splines afterwards.
5. **Water coupling**: shoreline / beach / underwater masks use the map's water elevation; river splines set a consistent surface; water level changes re-evaluate the masks.
6. **Stratum generator with rules**: priority-ordered layer recipes (cliff, rock, grass, sand, snow ...) with slope / height / curvature / water / erosion-mask inputs, writing the 8 + base layers and the terrain type grid together.
7. **Validation integration**: after a build, run the existing validators (stacked / blocked markers, slope view); a node can ask "are all start positions connected by a pathable route?" (flow-field pathing check on the result).

## 6. Splines and curves in detail

- Path object: control points with in / out tangents (Bezier) or Catmull-Rom; per point: width, height offset / absolute height, bank angle, falloff width; closed or open; snapping to the build grid and to other paths.
- Profile: a curve editor (Photoshop curves widget, built on `W.Slider`-style handles) maps distance-from-centre to height offset; presets (ramp, road with shoulders, V valley, U canyon, ridge, wall, terrace steps).
- Modes (all are field ops fed by a *distance-to-path* and *along-path* field): carve / raise / blend-to-target, match path height (ramp between two heights with a max grade limit shown live), river (carve + flat
  bed + water level + flow mask + banks erosion), strata along path (road texture), props / decals along path.
- Editing: viewport gizmo handles (we have the transform gizmo), insert / delete points, symmetry mirroring of paths, copy / paste, live preview of the result (preview field applied with revert).
- Storage: `Paths = { ... }` in the map's `_editor.lua` sidecar, applied results recorded as one undo entry each.

## 7. Erosion in detail

- **Grid hydraulic** (Mei et al. pipe model / Beyer particles as the second option): water, sediment, outflow flux per cell; capacity ∝ slope × speed; erode, deposit, evaporate; N iterations; outputs: height, wear,
  deposit, flow, flow accumulation. Parameters: rain, evaporation, capacity, erosion / deposition rates, iterations, solver steps, thermal talus coupling.
- **Thermal** already exists in the brush; the engine version is exact and tiled (talus, rate, passes) and reused by the brush.
- **Local erosion brush**: window = brush circle bounding box + border; boundary fixed to the surrounding heights; K iterations per dab (K from strength), results blended by the brush falloff; the engine keeps the window
  state between dabs of one stroke so water "keeps flowing" while you paint; the stroke is one undo entry.
- Presets: mountain, hills, canyon, alpine, desert, river valley, with sensible parameter sets; every parameter is a slider (rule: field + slider + − / +).
- Quality bar: compare against reference outputs (visual and statistical: ridge sharpness, drainage density) before calling it done; golden checksums for determinism.

## 8. UI and workflow

- New **Generate** workspace: node canvas (Maui bitmaps: nodes as draggable frames with a small thumbnail, wires as thin rotated bitmaps or line overlays, pan / zoom), inspector panel (sliders), mask / height thumbnails, a
  preview toggle that shows the graph result on the real terrain (and an overlay mode for masks), Build, Revert, seed randomise, and a variation gallery (N seeds as thumbnails). Panels follow the existing
  conventions (auto-imported `panels_*.lua`, `stack` hints).
- **Mask generator panel** (fast path, before the canvas exists): choose the layer, add rules from a list (slope range, height band, curvature, water, noise, flow) with sliders, preview as overlay, Apply = one undo step.
- Pipelines are files: save / load graphs, share presets (a `presets/` folder), import World Machine / Gaea results through the existing 16-bit PNG import, export masks as PNG.
- Everything respects symmetry, the playable area, the Mod / Mission workspaces (a mission map gets pads for its bases).

## 10. Risks and decisions

- **Native array transfer**: never marshal 10^6 numbers through Lua tables; handles only (also fixes the slowness of `ed_terrain_read_rect` for big areas).
- **Determinism across machines**: no fast-math, no uninitialised reads, fixed reduction order; document the compiler flags of the editor target.
- **Undo size**: whole height field per graph build is ~2 MB (1025²), fine; keep ≤ 200 entries as now.
- **Canvas UI cost**: Maui has no vector drawing; the node canvas needs wires from rotated bitmaps or the retained line overlay (`ed_overlay_*` can draw polylines in screen space): prototype first (T5 spike).
- **Open for the user**: (1) the node canvas versus a rule list first (recommendation: rule list + spline tool + erosion first, canvas after the engine proves out); (2) GPU compute (not in this D3D9 engine; CPU with threads
  is enough for 1025²); (3) bundled presets and sample graphs (recommendation: yes, a dozen maps' worth).

## 11. Stage T1 status: the native field engine (built 2026-10-18)

**Where**: native `moho/editor/EdFieldCore.{h,cpp}` (engine independent core: grids, thread pool, ops), `EdField.cpp` (the `ed_field_*` natives, document glue), `EdStrata.h` (whole-mask access to the strata shadow), a reader in `EdImageIO.cpp`; Lua `editor/runtime/lua/editor/fields.lua` (facade), `gui/panels_fields.lua` (debug panel), `selftest_fields.lua` + `selftest_fields_cases.lua` (self test and golden cases), `terraingen.lua` (now on field ops).
Tests: `python scripts/ed_native_tests.py` (engine free `EdFieldTest`: 70 golden cases at 1, 2, 3, 5 and 8 threads, property tests) and the in-editor `import('/lua/editor/selftest_fields.lua').Run()` (runs the same golden cases through the natives, plus commit / undo / mask / generator tests); `editor_inst.py selftests <tag>` picks it up through `selftests.extra`.

**Model**: a field is a float32 grid in native memory named by a number (a handle). Heights are world units (words / 128), masks 0..1. A grid has a world placement (`cell`, `ox`, `oz`): sample (x, z) lies at world (ox + x * cell, oz + z * cell); noise depends on the world position and the seed only, so a preview grid with `cell = 4` samples the same noise as the full resolution one and a field cropped from the map keeps its place. Lua never sees samples: ops make new fields from fields; only small reads, previews (`ed_field_preview` -> a coloured thumbnail written as DDS and shown by a Bitmap), stats and the commit cross back.
**Determinism**: every output sample is computed from the inputs alone (no accumulation across threads); reductions combine fixed 8 row chunks in chunk order; erosion is a double buffered, gather style update. Results are bit identical for any thread count (tested 1 .. 16) and the golden checksums are equal in the stand-alone test and in the editor. The core pins `fp_contract(off)`; all parameters are rounded to float32 first (Lua numbers are 32 bit), so a parameter means the same in a Lua call and in the native test.
**Ops (45)**: generators `const white perlin simplex ridged billow voronoi (f1 f2 edge id crack) gradient radial`; filters `blur box clamp invert abs gamma affine smoothstep threshold normalize quantize remap (monotone cubic or linear curve points) levels terrace warp offset rotate scale mirror (x z xz rot2 rot4 diag adiag, exact copies for symmetric maps) crop resize min max add sub mul blend (normal add sub mul screen overlay min max diff, mask, opacity)`; analysis `slope (degrees, gradient, rating = the engine's mobile footprint rule over a window, variation = the structure rule) height_band curvature water_below water_above water_depth shore distance (exact Euclidean, outside / inside / signed)`; erosion `thermal` (8 neighbours, talus = rise per run, optional mask). Sources: `ed_field_height(step, rect)` (the document's truth), `ed_field_stratum(i, raw)`, `ed_field_image(path)` (PNG16 / TIFF / raw), `ed_field_new`, `ed_field_from_table`.
**Commit**: `ed_field_commit_height` writes through the document in one stroke (ONE native undo step, exact by checksum; partial by mask and strength; any field shape is resampled onto the map); `ed_field_commit_mask` writes a strata paint mask and returns a raw copy of the old bytes, `fields.lua` builds the undo entry from it (`CommitMask`), and `Apply{height, masks}` makes heights + masks ONE history entry. Entries hold two raw native copies of the mask (0.5 MB at 512 x 512) until `entry.release()`.
**Speed** (1025 x 1025, Ryzen with 16 threads; one thread in brackets; measured in the editor, `selftest_fields.Bench()`): fBm perlin 5 octaves 12 ms (131), simplex 5 octaves 15 ms (151), voronoi 8 ms (91), gaussian blur sigma 4 3.6 ms (21) and sigma 30 16 ms (143), thermal erosion 50 iterations **146 ms (1225)**, slope 2.5 ms (16), slope rating window 2 2.6 ms (24), curvature 1.5 ms (10), distance field 9.7 ms (32), warp by noise 3.3 ms (28), rotate 2.9 ms (27), remap curve 1.5 ms (7), stats 0.8 ms, preview 128 x 128 4 ms, map heights -> field 2 ms. Writing a field into the map (one undo step, view refresh, tessellation) 164 ms, its undo 129 ms. `Generate terrain` on the 20 km map: 183 ms in total (the Lua loops of before took about half a minute).
**Debug panel** (`Fields`, a tab beside the console in the Terrain workspace): op list, sliders per op, Preview (live: a slider change re-runs the op on the working field and shows the thumbnail), Apply, Back, Clear, colours, "Commit to heights", "Commit to layer n". Generators start a field, filters work on the current one, binary ops combine it with the one before.
**Open / for T2 - T7**: no op reads a second *shape* (inputs must match in size, `blend` / `warp` fields come from the same `like`); P2 / P3 ops of section 4 (hydraulic erosion, flow accumulation, bilateral smooth, aspect, cavity, craters, dunes ...) are not in yet; there is no graph, caching or presets (T5); no spline objects (T4); the mask commit has no `terrain type` output and no props scatter (T2). New ops: add the function to `EdFieldCore.cpp`'s registry, a line to `selftest_fields_cases.lua`, run the native test with `--update` once (checks the thread independence first), and rebuild the engine.
**Engine build trap found on the way**: with the current compiler (MSVC 1951) an optimised `lua/LuaObject.cpp` crashes the Lua state at startup (`resize` of the globals table); `main_ed.vcxproj` compiles that one file with `Optimization = Disabled` now. A full rebuild without that line gives an exe that dies in `luaL_openlib`.

## 12. Stage T4 status: the spline / curve tool (built 2026-10-18)

**Where**: native `moho/editor/EdFieldPath.cpp` (6 ops, registered through `RegisterOp`, engine independent like the core) and its stand-alone test `tests/EdPathTest.cpp` (`python scripts/ed_path_test.py [--update]`); Lua `paths.lua` (model, curve sampling, heights and grade, symmetry images, Preview / Apply / Bake, scatter, sidecar), `pathtool.lua` (the viewport tool and the overlay lines), `gui/panels_paths.lua` (the Paths panel, a tab beside Layers in the Terrain workspace), `gui/curvewidget.lua` (the profile curve editor), `selftest_paths.lua` + `selftest_paths_cases.lua` (self test; goldens shared with the native test). Small edits in shared files: `ui.lua` (tool `Paths`), `overlay.lua` (calls `pathtool.Draw`), `gizmo.lua` (provider `paths`), `history.lua` (`DropRedo`, `PushQuiet`, hooks `Before` / `PreUndo`), `gui/panels_objects.lua` (Ctrl+C / V / D and Delete act on paths while the tool is active), `mods.lua` + `map.lua` (sidecar text and load).

**Model**: a path is a Catmull-Rom or Bezier curve through control points `{ x, z, w, f, h, abs, bank, ho, hi }` (half width, falloff width beyond it, height, pinned flag, bank angle, tangent handles for Bezier; handles mirror unless Alt is held). Per path: `mode` (carve, raise, level, ramp, road, river), `closed`, `sym` (the symmetry images of the map are shaped too), `strength`, `erosion` (thermal passes over the banks), `grade` / `limitGrade`, `interp`, the `profile` (curve points, smooth, symmetric), up to two `strata` entries, `scatter` (props) and `decals`. Stored as `Paths = { ... }` in the map's `_editor.lua` sidecar; every edit is an undo entry holding a whole-state snapshot (slider drags merge into one entry within 1.5 s).
**Heights**: carve / raise add `h * weight` (offset mode); level / ramp / road blend the terrain towards a target height (`h` above the ground under the point, or the absolute height when pinned); unpinned points between two pinned ones lie on the straight line (arc length) between them; with `limitGrade` the plan is relaxed to the maximum grade (pinned points stay; what cannot be reached is flagged). River: bed = water level - depth (`h`), never uphill along the way of travel, carve only (`clip = min`), width / falloff / profile give flat bed and banks; the texture layers along the path (core, bank) are the flow / bank masks of the river. The weight across the section is the profile curve (x = distance / half width, v = share of the effect; monotone cubic or polyline) up to the half width, then the end value fades to 0 over the falloff. Presets: ramp, road with shoulders, V valley, U canyon, ridge, wall, terrace steps; the curve widget adds, drags and deletes points.
**Native ops** (all outputs from the inputs alone, bit identical for any thread count; golden cases in `selftest_paths_cases.lua`, 26 cases at 1, 2, 3, 5, 8 threads, plus property tests against brute force): `path_dist` (distance, signed with `signed`, `far` outside the reach), `path_along` (arc length, `normalize`), `path_u` (cross-section coordinate), `path_mask` (`kind` weight | core | reach | bank), `path_shape` (the shaping: `mode` offset | target, `clip` none | min | max, `strength`, `mask`), `path_paste` (add / sub / set / max / min a small field into a bigger one at its world placement: the building block of "replace the previous result"). The curve is sampled in Lua into a dense polyline of 8 numbers per point (x, z, y, w, f, bank, off, s); a path patch of a few thousand samples takes a few milliseconds.
**Non-destructive apply**: Apply measures what the path changed (`delta` = new heights - heights without the path, quantised to the map's words, kept as a native field with the rect it covers) and keeps it; the next Apply first subtracts the old delta (`path_paste` sub) from the current terrain, so edits made elsewhere (or in the same area) after the first Apply survive, then shapes again and commits: ONE history entry (heights, strata, props and decals together: `Fields.Apply` plus the path's own undo hooks). Bake forgets the delta (the next Apply stacks on the terrain); Remove result takes it off again. Strata work the same way on the whole mask (delta fields per layer, the commit touches exactly the covered samples); props and decals of a path are tracked as lists and replaced. Limitation: the results live in memory; after the map is saved and opened again an applied path counts as baked (`wasApplied`, shown in the panel) - a native writer for the delta fields (16 bit PNG next to the sidecar) is the missing piece.
**Preview**: the result is written into the real terrain as a native document step without a history entry (revert = undo that step), re-run when the model changes (at most 4 times a second while Live preview is on). An undo or redo request with a preview showing only takes the preview off; a brush stroke that lands on a preview turns it into an ordinary history entry placed before the stroke (`history.lua` hooks), so history and native stack never drift; leaving the Paths tool reverts the preview.
**Grade check**: the planned grade (rise / run over about 3 units) is drawn live: the stretches above the limit are red on the path in the viewport, the panel shows the maximum and the share over the limit; "Check pathing" rates the current terrain along the path corridor (middle 60 % of the half width, without the end caps) with the engine's mobile footprint rule (`slope` rating, 0.75 blocks every land unit) and reports the blocked share.
**Tool**: Draw mode (click ground to add points, click a line to insert, click the first point to close), Edit mode (click / Shift+click points, drag points, drag tangent handles, Ctrl+click a line to insert, click a line to select the path, click ground to deselect); the transform gizmo moves / turns the selected points (the whole path when none is selected); Snap rounds point positions to 1, 2, 4 or 8 units (the build grid); Delete removes selected points (then the path); Ctrl+C / V / D copy, paste at the pointer and duplicate. Overlay: the path line (yellow = selected), width edges (solid = half width, dim = end of the falloff), direction arrow, control squares, handles.
**Not done / ideas**: persistence of the applied results (see above); a terrain-type output for the strata; mirror-as-copy (the `sym` flag shapes the images without creating paths); bank erosion is plain thermal talus (the T3 hydraulic ops can replace it); per-point profile overrides; the node graph (T5) can take `path_*` ops as nodes. The mouse drags (points, handles, curve widget, gizmo) are covered by code review and the model-level tests only: the headless test harness cannot press mouse buttons.
## 12. Stage T2 status: mask generator, stratum recipes, scatter (built 2026-10-18)

**Where**: Lua only on top of the T1 engine, plus a few small native additions (below). `maskgen.lua` (rules, evaluation, preview, outputs), `recipes.lua` (stratum recipe presets), `scatter.lua` (props and decals scatter), panels `gui/panels_maskgen.lua` (**Mask generator**), `gui/panels_recipes.lua` (**Stratum recipes**), `gui/panels_scatter.lua` (**Props scatter**) - tabs beside the console in the Terrain workspace; `selftest_maskgen.lua` (77 checks, in `selftests.extra`). One hook into `overlay.lua` (2 lines: `maskgen.DrawOverlay` per frame, `OverlayReset` on clear).

**Mask generator** (tab `Mask generator`): a rule list, evaluated top to bottom in C++ (a rule is a few field ops; a whole list on a 1025 map takes 3 - 40 ms at preview resolution). *Source rules*: slope (degrees, soft edge), **unit class slope** (the engine's own footprint rule: land small / medium / large, experimental, structure ground variation; mask the "blocked" or the "passable" ground), height band, curvature (convex ridges / concave gullies), aspect (ground facing an azimuth: sun side), water (land above / under water / shore band, relative to the map's water surface), noise (perlin, simplex, ridged, billow), flow (drainage area: rivers), position (linear gradient or distance from the middle: edge bands), texture layer (what a layer covers, optionally only where visible), free of layers above (the strata cascade: the product of `1 - mask` over the layers above), near a texture layer (distance), constant. Each source combines with the result so far by `and` (the smaller), `or` (the larger), `multiply`, `difference` (minus) or `add`; a per rule `Not` inverts it first. *Modifier rules* work on the result: not, blur, grow, shrink, remove specks (open), fill holes (close), threshold, smooth step, amount. Grow / shrink / open / close use the exact Euclidean distance transform. Ten starting points (cliffs, ground land units cannot cross, buildable flat ground, beach, snow caps, ridge tops, gullies, sun-facing slopes, dirt patches, map edge band). Every number is a field + slider + minus / plus.
**Preview**: live, as a 128 px thumbnail and as red squares on the ground around the camera (`Show on map`: everything of the map the camera sees, up to 290 x 290 nodes, 2 / 4 / 8 units per node when zoomed out, redrawn when the visible window or the mask changes; `overlaywin.lua`). The preview runs on every second height sample on maps over 700 units (slope rules read slightly coarser ground there); applying always runs at full resolution.
**Outputs**: `Apply to layer` writes the mask into the paint mask of texture layer 1..8 (replace / add to / subtract from, a strength, and `Layers above take away` = multiply by the ground the layers above leave free), one undo step; `Apply to terrain type` sets a TypeCode where the mask is above a threshold, one undo step; `Types from layers` is the existing generator.

**Stratum recipes** (tab `Stratum recipes`): a preset lists the kinds of ground from the bottom up and makes each one's mask from rules: Temperate (grass, dirt patches, sand shore, rock, cliff), Alpine (grass, dirt, rock, snow above a snow line, cliff), Desert, Arctic, Rocky. Knobs per preset: cliff and rock slope angle, snow line (share of the height range), beach width, edge breakup (noise), patch size, seed. Every kind gets a texture layer (0 = skip; the first kind is the Base layer); `Layers in order`, or `Match textures` = by the names of the textures the layers hold now (dirt, sand, rock, snow ...). `Show kind on map` previews one kind; `Apply recipe` writes the paint masks of all layers and (switch `Terrain types too`) the terrain-type grid **as one undo step**. The layers above take away: higher layers cover lower ones in the shader, and the terrain type of a cell is the default type of the texture of the layer seen most there (`terraintype.lua` DefaultFor / the user's assignments), the base share being what nothing covers; layers outside the recipe still count. The result lists the share of each kind.

**Props scatter** (tab `Props scatter`): blueprint list with weights (`Add selected prop` takes the one picked in the Props panel), density mask = the Mask generator's rules (switch `Density from the mask rules`; no rules = everywhere), slope and height limits, scale range, random heading, minimum distance, seed, count, margin, `Fill`. Dart throwing on a spatial hash = Poisson disc sampling with a variable density (the mask value is the acceptance probability), from a Wichmann-Hill stream (exact in 32 bit floats), so the same settings on the same terrain place the same props. **Symmetry aware**: with a symmetry mode on, a prop is judged once at its original position and placed together with all its images (heading mirrored or turned, `Symmetry.Heading`), all keeping the minimum distance. `Count` shows what would be placed, `Scatter` places it as one undo step (5000 props: 0.2 s, undo 2 s: the sim callbacks of `Map.AddProp` / `RemoveProp`). **Decals**: the switch `Decals instead of props` scatters albedo decals (with their normals decals) by the same rules; size = `Decal size` x scale.

## 12. Stage T3 status: the erosion suite and the erosion brushes (built 2026-10-18)

**Where**: native `moho/editor/EdErosion.{h,cpp}` (engine independent: solvers, brush session; registers its ops in the field engine's table through `RegisterOp`), `EdErosionLua.cpp` (the `ed_erode_*` natives), `EdField.cpp` (`ed_field_op_multi`), tests `tests/EdErosionTest.cpp`; Lua `erosion.lua` (solvers, presets, preview, Apply), `erosionbrush.lua` (brushes), `gui/panels_erosion.lua` (panel), `erosionquality.lua` (statistics), `selftest_erosion.lua` + `selftest_erosion_cases.lua` (self test and golden cases), `terrain.lua` (brush modes), `ui.lua` (tools Rain, Deposit).
**Ops** (all take `a` = height field, optional `mask` = erodibility 0..1, `output = height | wear | deposit | flow | water | sediment`; `ed_field_op_multi` returns the main field and a table of all the others from one run, plus `accum` = drainage accumulation as a 0..1 mask):

| Op | What it does |
|---|---|
| `erode_hydraulic` | Pipe / shallow water model (Mei et al.) on the grid: rain, outflow fluxes from the water surface differences (scaled so no cell gives away more than it has), velocity, sediment capacity = capacity x sin(slope) x speed x depth factor, dissolving and settling, **sediment travels with the water through the same pipes (upwind, conserves the total)**, evaporation, thermal slides coupled in every n steps. Open edges (outer ring fixed, drains) or closed. Dissolving is capped by the drop to the lowest neighbour (`cut_limit`): erosion never digs pits. |
| `erode_droplet` | Particle erosion (Beyer / Lague): droplets with inertia, capacity, erosion radius, deposit. Tiles of a fixed size in four colour phases (tiles of one colour never touch), a random stream per tile and round: **bit identical for any thread count**. Droplets steer on the pit filled terrain (`drain_pits`), dissolve nothing inside filled basins and deposit only up to the spill level, so basins drain and their rims are cut instead of the usual flat sediment discs; no craters where a droplet lands (nothing is picked up in the first two steps); a cell is dug at most `round_cut` per round. |
| `erode_stream` | Stream power incision on a drainage network: pit breaching (priority flood with carving: the lowest rim of every closed depression is cut), multiple flow direction accumulation, incision = k x (area - area_min)^m x slope, never more than a share of the drop to the lowest neighbour, smoothed (`widen`) so channels get a width, hillslope diffusion between iterations. Output `flow` = catchment area in cells. |
| `slope_area`, `basin_depth` | Quality statistics as ops: slope against drainage area (binned by log2), depth of closed depressions (also a lake mask). |

The grid and droplet ops smooth the *change* they made with a 3 x 3 binomial kernel (`smooth`, `smooth_passes`) to take the cell scale noise out (the pipe model stair steps along its four directions, droplets leave pits): measured, the fine scale roughness `hf` of Hills fell from 2.95 to 1.5 (stock maps 1.4 - 1.95, see below).

**Update 2026-10-22 (3): the erosion brush is droplet based (it went beyond its circle, left a square, dug in rows).** Causes in the earlier brush (the pipe model of the grid solver on a square window, `RunHydro` in `ErodeSession::Dab`): (1) only rain and dissolving were multiplied by the brush weight; settling (`deposit = deposition * (surplus)`) and the water flow were not, and the rim of the window was a pinned sink, so sediment landed over the whole window: changes up to its edge (a rectangle with a straight edge); the thermal step also handed material to the ring outside the brush; (2) water, sediment and fluxes of the whole map were kept between dabs but zeroed on the rim of every window and left frozen outside the next one: stripes with straight edges at the spacing of the dabs, and results that depended on the window size; the dig was limited to the brush while the water fed in only under it, so it concentrated where the flux was largest (the middle and where the water left); (3) four pipes per cell: a diamond of settled sediment and rills along the grid axes (the comb); (4) `Finish` dumped all suspended sediment into the dirty rectangle. The Deposit brush dumps the sediment per droplet on a jittered grid (an even heap). The session keeps only the float heights (no water state), `Finish` returns false. **Update 2026-10-22 (4): the erosion nodes blurred and melted instead of carving (judged by rendering).** Method: a stand-alone driver (`EdFieldCore.cpp` + `EdErosion.cpp` + `EdFieldEro2.cpp`, g++) ran the graph's chain (Rock and soil 60 / 0.6 -> Droplet defaults -> Hydraulic 210 / 0.004) on two procedural terrains at 1 sample per unit (320 x 320: rolling hills with cliffed mesas and a square plateau, heights 5 - 75; a rough mountain field), and Python wrote hillshades (sun 315 degrees, altitude 40), slope and drainage pictures, plus band energies of the height spectrum (what the run keeps at 4 - 8, 8 - 16, 16 - 32, 32 - 64 sample wavelengths). Causes found, each with the evidence that decided it:
(a) **Droplet feedback (the main one).** `rounds` (default 4, not in the UI) is how often the steering surface is refreshed; a droplet reads the surface of its round's start, so droplets of one round never see each other's gullies. With 4 rounds every droplet dug a lone groove: a smear of short worms on the plains, soft cliffs, no branching. 16 rounds already branch, 32 give gullies that capture their neighbours, join downhill and leave sharp ridges between them. The default is now 32 (`rounds` is a slider, "Feedback rounds"); measured (EdErosionTest `TestFeedbackAndHierarchy`, smooth hills): fine relief (mean |laplacian|) 0.0145 input -> 0.024 (4 rounds) -> 0.047 (32); share of the samples moved by more than 0.5 units 0.023 -> 0.48. Cost: one pit fill per round, 1025 x 1025 about 5 s -> 11 s on 4 cores (the coarse preview is not noticeable). `drain_pits = 0` (live steering) was tried and is not an alternative: it fills basins and flattens the field (relief 16 -> 4).
(b) **Hydraulic erosion runs after it and melts.** The pipe model moves material from slopes to the low ground and smooths: 150 - 210 steps removed a third of the 16 - 64 unit relief of the droplet result (band 32 - 64: 96 -> 63) and filled the valleys flat. 40 / 70 / 100 steps lose 8% / 15% / 21% of that band and crisp the gullies, so the default is a compromise at 60. The default is 60 (was 150). Making the capacity depend on water depth beyond `depth_max` (a `focus` exponent: channels do form, but as rippled, grid aligned noise) and taking the large scale part of the change back (a `keep_form` filter: no effect, the loss is local) were tried and dropped. The pipe model stays what it is good at: soft deposits, rounded basins.
(c) **Rock and soil rounded every cliff.** Soil slid at talus 0.35 (19 degrees), rock at 1.2: a cliff of 9 units and slope 3 turned into a 30 sample wide ramp. Now soil 0.4, soil talus 0.7 (repose angle of loose soil, 35 degrees), rock talus 3: the spectrum of the mountain field is kept (band 16 - 32: -10% -> -1%), cliffs stay. (graphnodes_t7.lua defaults; the C++ defaults of the op are unchanged.)
(d) **Stream power: k did nothing.** The cut was `min(k * sqrt(area) * slope, max_cut * drop)`; for any k above ~0.1 the cap won in every channel cell (k = 0.5 and k = 4 differ by 0.007 units mean, k = 0.05 and 0.5 by 0.08), so all channels cut alike and the network had no hierarchy. Now the share `F / (1 + F)` of `max_cut`, F = k * (area - area_min)^m: small streams cut slowly, rivers up to the cap (test: the mean change grows with k). Valleys widen with the catchment (`width_vary`, extra smoothing passes of the incision, Horner scheme: one pass over the map per smoothing pass in total, scaled back by the centre weight of the kernel so k keeps its meaning). `route_every` rebuilds the drainage network only every n steps (3: the same picture at a third of the time, test). Defaults k 0.05, 20 steps. **Spike: how to draw a node canvas in Maui.** Maui has no vector drawing, no rotation of a Bitmap (only `SetUV`) and no clipping. Options looked at: (a) wires as rotated bitmaps: impossible (no rotation); (b) `ed_overlay_*`, the retained line overlay: draws terrain aligned lines in the *world*, not in screen space; (c) rasterise the wires into a texture (`ed_dds_write`) every frame: a Lua loop per pixel, far too slow, and a native line rasteriser would be a new engine build for little gain; (d) **pooled axis aligned Bitmaps**. Chosen: (d). A node is one Bitmap frame whose children (header, title, thumbnail, port dots, labels) follow it, so moving a node sets four numbers on one control; a wire is an elbow (out, across, in; five pieces when it runs backwards) of 2 - 3 pixel wide solid bitmaps from a pool; every piece is cut to the canvas rectangle in Lua (a node that is only partly visible shows its cut frame without contents; below zoom 0.75 the port labels go, titles stay). Pan = middle or right drag, zoom = wheel about the pointer (0.35 - 1.6), left drag on the background = box select (Shift adds), drag a node = move the selection (snaps to 8), drag from a port to a port = wire, drag a wired input away = take the wire off. Measured in the editor (60 nodes): relayout 4 - 6 ms, one drag step 4 ms, first show (views, evaluation, thumbnails) 183 ms. The drag logic is in plain functions (`Pn.DragNode`, `DragWire`, `DragBox`, `Wheel` ...) that the `Dragger` only forwards to, so `selftest_graph` runs the drags without a mouse; what it cannot test is the engine's own hit testing (the press reaching the right control), checked by code review only. Pieces that do not use an event return false so that it bubbles; the wheel is handled on the nodes and on the background.

**Model** (`graph.lua`). A graph is `{ name, seed, nodes = { { id, type, x, y, params, label, off } }, wires = { { fromId, outPort, toId, inPort } }, nextId, view }`; one wire per input; port types `height` and `mask` (both fields, they connect freely, the colour tells what the node means), `points` (a path) and `number` (a single value: a number output wired into the number port of a parameter overrides that parameter; ports exist for the parameters marked `wire`). Loops are refused when connecting (and reported when a file has one). Edits are undoable in the graph's own stack (`Undo` / `Redo`, 100 entries; whole-graph snapshots; one slider drag is one entry); Undo / Redo / Copy / Cut / Paste / Duplicate / Delete work on the graph while the pointer is over the canvas (`Commands.Intercept`), elsewhere on the map. Files: `graphs/<name>.lua` next to the engine's working directory (a plain `return { ... }` data table, listed through a VFS mount `/usergraphs`), and `Graph = { ... }` in the map's `_editor.lua` sidecar (written with the map, read when it opens). **Native ops** (all outputs from the inputs alone; sequential sweeps / searches are ordered, so results are bit identical for any thread count):

| Op | What it does |
|---|---|
| `pad_flatten` | `a` = heights. Base pads and resource rings. `pads` = 6 numbers per pad `x, z, half, skirt, y, group`: a flat square core of half size `half` whose edges are **snapped outward to the build grid** (`grid`, default 1; so whole cells are level) plus a smoothstep skirt of width `skirt` (Euclidean distance to the core rectangle). Height: `group` 0 = the mean (`level` 0) / lowest (1) / highest (2) of the pad's own core, `group` k >= 1 = ONE height shared by all pads of the group (a mass cluster on one level), `group` -1 = absolute `y`. Targets are quantised to 1 / `word` (128) units; pads apply in list order; `strength`; `output` height / weight (largest pad weight) / core. |
| `symmetrize` | `a` = any field (heights, a mask, codes). The master wedge is copied onto the rest by the symmetry group: `mode` mirror_x / mirror_z / mirror_xz / diag / adiag / diag_both / rot2 / rot4 / **rotn** (`n` = any N-fold turn 2..16, `angle` turns the wedge start). Centre `cx, cz` (world, default the middle), `side` / `sector` = the master wedge (mirror_x: 0 left, 1 right; mirror_z: 0 upper; quarters: upper left, upper right, lower right, lower left), `combine` copy / avg / max / min over all images, `seam` blends copy towards avg near the wedge borders (soft borders for turns), `nearest` reads the closest sample (terrain-type codes). With the centre on the lattice and quarter turns / mirrors every output sample is an exact copy, so the result is invariant under the group bit for bit (tested), and it equals the `mirror` op of the core for the same master half. "Seed compatible" means: a noise graph with any seed followed by this op is symmetric by construction, and the wedge / combine choices are the variants of one seed. |
| `slope_limit` | `a` = heights. Makes every neighbouring pair differ by at most `(limit - margin) * cell`: the engine's pathing rule (steepest neighbouring difference over the footprint window, 0.75 blocks land units) then holds for **every** unit class, since the window only gathers more of the same pairs. Exact, not iterative: with the 4-neighbour L1 metric the **highest Lipschitz surface below the input** (`mode lower`, cuts peaks) and the **lowest above it** (`raise`, fills valleys) come out of one two-sweep chamfer pass; `both` = their convex blend (`balance` 0 fill .. 1 cut), which is Lipschitz too. Verified against the brute force min / max of `h(q) +- L |p - q|`. `strength` and `mask` blend the result into the input (outside a mask the guarantee ends at the mask edge). |
| `reach` | `a` = passable mask, optional `b` = cost multiplier. Travel distance (8 neighbours, no corner cutting, optional per-cell cost) from `src` (x, z pairs, snapped to the nearest passable sample within `snap`); unreachable = `unreach`. |
| `regions` | `a` = passable mask. Connected regions (`connectivity` 4 / 8, no corner cutting): `mode label` (1..N in raster order, 0 blocked) or `size` (area in world units squared). |

**Base pads and resource rings** (`sctools.lua`, section Pads): the markers drive everything. `Collect()` reads `ARMY_n` (start pads: core half 8, skirt 10), Mass (half 2, skirt 4) and Hydrocarbon (half 4, skirt 5) markers; every size is a slider. **Ring**: resource markers within `ringRadius` (30) of a start join that start's height group, so the base and its mass ring are one level; **cluster**: the other markers of one kind closer than `clusterDist` (16) share a height; the rest are levelled one by one. `Apply()` is non-destructive like the paths: the result is kept as `delta = new - base`, the next Apply first subtracts the old delta (`path_paste sub`), so moving a marker and applying again *replaces* the pads instead of stacking them; ONE history entry that also moves the markers' `y` to the new ground and follows undo / redo. `Stale()` says the markers moved since the last Apply, **Auto** re-applies by itself half a second after the markers stopped (not while undone steps wait for a redo). `PadOverrides` (a start pad as a plateau at an absolute height) and `PadExtras` (pads without a marker, e.g. the hub plaza) are what the skeleton generator uses. Limitation as in T4: the result lives in memory; after save and reload the pads count as baked (the next Apply flattens the already level core again, which is idempotent, but the skirt is blended once more).

**Symmetry as a first class op** (section Symmetry): `Symmetrize()` takes the mode and centre of `symmetry.lua` (the symmetry the marker tools and brushes use), the master part (a button per part) and makes heights, any of the 8 texture layers and the terrain-type grid symmetric in ONE undo entry (undo is exact by checksum). `MarkerCheck()` lists markers whose symmetric image (by `Symmetry.Points`) is missing: the check against the marker symmetry. The mask grids are half resolution (cell 2, origin 1) and the type grid has cell 1, origin 0.5: the map centre is 128, so mirror and quarter-turn images land on the lattices exactly.

**Pathable slope limit and ramp check** (section Slope limit): `SlopeApply()` runs `slope_limit` with the panel values (limit, margin 0.03 so the 1/128 quantisation cannot break it, mode, balance, strength, optionally only inside a texture layer's paint with a soft edge) and commits ONE history entry; the report shows the blocked share per unit class (small, medium, large, experimental) before and after, with a thumbnail of the ground too steep for the chosen class. Measured: after the limit no class sees a rating above 0.75. `RampProfile(points)` / `RampPath(id)` give the grade along any route on the current terrain (grade over a run of 3 units): maximum, mean, share over the limit, height range, and the stretches over the limit with their positions (the worst point of each); the panel button checks the selected path.

**Map skeleton generator** (`skeleton.lua`, section Skeleton): from the start positions (`ARMY_n`) and a style it lays down **ordinary Paths objects** (tag `skeleton`; the user edits, moves and re-applies them afterwards) and pads. Connections: `ring` (neighbours around the middle), `hub` (every base to a plaza in the middle), `both`; `lanes` parallel lanes, lane half width / falloff / grade limit / bend are sliders. Styles: **Open** = ramp paths pinned to the base heights with the grade limit (lane = a guaranteed pathable corridor); **Ridge** = the same lanes with a tapered raised ridge along both sides; **Ramps and chokes** = every base a plateau (a pad at ground + height with steep sides) with ramp paths pinned from the plateau top to the ground and a lane between two ramp bottoms that narrows to a choke width in the middle; **Islands** = a carved moat ring around every base below the water level and causeways (level paths) between the islands. Every path starts and ends inside a flat pad, where the terrain already has the pinned height, so paths join pads without a step; `ApplyAll()` applies pads and paths in order and finally (switch **Smooth lanes**) the slope limit over the lane corridors (path reach masks) to take out the small steps where a path leaves a pad skirt, all as ONE undo entry (`History.Merge`); `Generate()` replaces an earlier skeleton (its applied results are taken off first). Measured on rolling hills with four bases: all four styles generate 4 - 16 paths, apply as one entry, undo, and leave every base connected by land.

**Water coupling** (section Water): a definition = a kind (Beach: land strip above the water, only where the ground is gentle; Shore line; Shallows; Underwater; Deep water), a texture layer, strength, width / depth / softness / steepest beach as sliders. The mask is evaluated at the map's water elevation (`world.lua`, `water_elev`) and written into its layer as `layer + (1 - layer) * mask` over what the layer held before; the definition remembers the layer before (`base`) and what it wrote (`last`), so **applying again replaces its own earlier result and keeps what the user painted afterwards** (cells whose value differs from `last`). **Live**: after the water level changed and stayed put for 0.6 s every applied definition is evaluated again (one undo entry; not while undone steps wait for a redo); `OutOfDate()` and the panel say when a mask was made at another level. Measured: a mask re-evaluated after the level fell from 20 to 14 follows the new shore, the dry ground is no longer painted, a blob painted in between survives.

**Terrain checks** (`terrainchecks.lua`, panel Terrain checks; call `TerrainChecks.Run()` after a graph build): (1) the marker validators of `validate.lua` (stacked, off the build grid, blocked by the sim's own build check, map findings; the sim answers within a few frames and joins the list by itself); (2) the base area of every start (blocked share inside the radius for the chosen unit class) and the ground variation under every resource marker (structure rule 1.1); (3) **pathing connectivity**: the passable ground of the layer land (slope rule, no water deeper than `wade`), hover (land or any water) and amphibious (slope rule only) is cut into regions with the native `regions` op; every start must lie in one region (error with the position of the stranded start), resource markers outside every start's region are reported, and the route length from the first start to the others is measured with `reach` (a detour longer than N x the straight distance is a warning); (4) the grade along every ramp / road / level path of the Paths tool (worst point); (5) marker symmetry, stale pads, out-of-date water masks. Each problem carries a position; a click in the list moves the camera there; **Auto after edits** re-runs about a second after the history changed. This is not the engine's own path query: it is the engine's slope rule on the height field, so props, terrain-type cliffs, the playable area and units are not considered, and the water rule of hover / amphibious is an approximation of the engine's layers.

**Tests**: `python scripts/ed_sc_test.py` (native: goldens at 5 thread counts, mirror ops equal to the core `mirror` op, group invariance exact, Lipschitz envelopes against brute force, pad core levels and group heights, reach on an open field equals the octile formula, walls, corner cutting, regions); in the editor `import('/lua/editor/selftest_sctools.lua').Run()` (96 checks: the same goldens through the natives at 1, 3 and 16 threads, pads with rings / clusters / moved markers / undo / redo / remove / Auto tick, symmetry of heights + layer + types with exact undo, marker check, slope limit and undo, layer restricted limit, ramp grades, water masks with a level change and preserved user paint, Live tick, connectivity with a wall, steep base ground, all four skeleton styles with one undo entry and connected bases; repeatable in one session).

**Not done / ideas**: pad results and skeleton state are not saved with the map (the skeleton paths are, as paths; the pad result is baked after reload); no `Mirror markers` command (the check lists the missing partners, creating them is the marker tools' job); the skeleton is bases + lanes, not terrain features (no forests / mountains between lanes: the T5 graph can add them); `slope_limit` has no pinned cells (an edit that must keep a spot fixed uses the mask); a native passable-mask op fusing slope + water in one pass would halve the check time on 2049 maps.

Greyscale integer images are read as stored (no WIC colour conversion: a 16-bit value stays exact), colour images give a channel (gray = luma, r, g, b, a). **Resampling** (`img_resample`, separable, scale-aware kernels): `align = cell` (the image covers the N cells, pixel centres on cell centres: a 1024 / 2048 image on a 1025-sample map), `corner` (first / last pixel on first / last sample: a 1025 image is the identity, exact for every filter); `auto` picks corner when the image has exactly the region's samples. Filters bilinear, bicubic (Catmull-Rom), Lanczos 3, nearest; the kernel is widened by the shrink factor, so a 2048 image on a 1025 map is low-pass filtered (no aliasing); edges replicate.

**Regions and blends.** Whole map, playable area (AREA_1) or a rectangle (sliders in samples); `rect_mask` feathers the borders that are not the map's border; blend replace / add / max / min / by mask image (an image over the same region), strength 0..1; one `blend` op with the mask. Pads: `keep` (discs around start positions and mass / hydrocarbon markers keep the terrain, soft rim) or `flatten` (the imported terrain is levelled there at the height it had at the centre). There was no pad logic in the editor to reuse; this is it, driven by the markers. The whole import is ONE undo entry (`Fields.Apply`).

**Masks.** A list of files (several files, or the r / g / b / a channels of a splat image), each to a texture layer (written from the highest layer down with `takeAway`, so a layer takes away from the ones above), the terrain-type grid (code + threshold) or a named mask. Named masks are kept in the editor (file + channel in the sidecar, read when needed) and are available to the mask generator as the new rule "Imported mask" (`maskgen.lua`, `SOURCE.named`, slot number; an empty slot masks nothing). ONE undo entry for the set.

**Export** (`interopexport.lua`): heightmap (16 / 32 bit, png / tif / raw, normalised or absolute, the map's own or a fixed range) with `<name>_height.json` (mode, min, max, size, water level: the import picks it up when the file is chosen, so the round trip needs no typing), water, slope, flow, wear / deposit (curvature based), every painted layer, terrain types, markers (CSV and two disc images), playable area, `README_scale.txt` (map size, N + 1 grid, ranges, Gaea / World Machine settings). All images are on the height grid. Round trip exactness is a selftest for PNG 16 normalised / absolute, TIFF 16, float TIFF normalised / absolute and raw: a map exported and imported again has the same checksum (the 16-bit normalised quantisation is below half a height word for ranges under 512 units).

**Live link** (`Link` in `interop.lua`, ticked by the Interop panel module about 4 times a second): watches the import's files (or every image of a folder) by `size:mtime` stamp; a change must be seen twice in a row (the tool has finished writing), then the heightmap is imported with the saved settings; the previous live import is undone first when it is still the latest history entry, so any number of rebuilds are ONE undo step; Revert takes it back. Changed mask files re-apply the mask list.

**Settings per map**: `Interop = { import, masks, named, link, export }` in `_editor.lua` (`interop.lua: SidecarText / ApplyData`), written only when something differs from the defaults.

**Tests**: `selftest_interop` (100 checks: file natives, mapping, alignment per filter, orientation, region blends, pads, masks, named mask in the generator, export + exact round trips, live link, sidecar, no field leaks), `scripts/ed_interop_test.py`.

## 14. Texture normals and terrain type overlay fixes (2026-10-18)

**Normals of painted layers.** The terrain shader reads a paint mask byte `m` as `saturate(2 m / 255 - 1)` in the albedo passes (bytes up to 127 mean "nothing") but as `saturate(m / 255)` in the normal passes (`TerrainNormalsPS`, `TerrainNormalsXP`). A cell with almost no paint (the soft edge of an erased stroke, a faint mask) got half of the layer's normal map: the normals "stayed" where the albedo had gone, and did not follow the mask (measured: a 4 % mask changed the picture by 23 % of what a full mask does, with the fix by 4.6 %). The editor now shadows `/effects/terrain.fx` with a generated copy (`editor/tools/gen_terrain_fx.py`, `--check`; FAF's file plus two changed lines, hash of the base in the header; `editor/runtime/override/effects/terrain.fx`) whose normal passes use the albedo's weight. Only the editor shows this; the game still renders FAF's file. Removing a layer's texture (`strata.lua RemoveTexture`, Layers panel and context menu) now also clears what it painted, as one undo step: a painted layer without a texture used to lerp its transparent colour over the layers below by the mask alone (black terrain), and the normal map of the removed texture stayed in the blend.
**Terrain type overlay.** `Show on map` drew a window of 140 x 140 cells around the point the camera looked at, so a zoomed out view showed a rectangle that did not match the map and moved when the camera moved. `overlaywin.lua` now fits the node grid to everything the camera sees (the view's corners and edge middles on the ground, a corner at the sky = the whole map), at 1, 2, 4 ... 64 units per node so that at most 290 nodes per side are needed; `ed_overlay_nodes` takes the node distance as a 9th argument (`step`, `EdOverlay.cpp`); `terraintype.lua NodeCodes` gives the code under every node. The mask generator's preview uses the same window. Verified with screenshots at several zoom levels and camera positions on a 5 km and a 20 km map (a marked block of terrain type 150 lines up with the same block painted into a texture layer to about one unit).

## 16. The Generate section of the Fields panel: natural noise that mixes into the map (2026-10-22)

**Problem**: a generator made a 0..1 field and `Commit to heights` wrote it over the whole map (the map became flat at 0..1, or lost its own relief); the noise had visible lattice seams and a preferred axis.
**Causes found** (rendered and measured with `scripts` harness: hillshade PNGs and statistics): (1) every octave of `perlin` / `simplex` / `ridged` / `billow` sits on the same lattice (lacunarity 2, no offset): all octaves are exactly 0 at the coarse lattice points, so the sum is exactly 0.5 on a visible grid (measured: mean |v - 0.5| on the coarse lattice points 0.000 against 0.084 elsewhere) and ridged / billow show straight seams; (2) the gradient noise has only 8 gradient directions (4 on the axes); (3) octaves down to 5 units wide make a crumpled surface; (4) no way to mix a generated field into the existing ground.
**Native** (`EdFieldCore.h` OctaveFrame / Gradients64, `EdFieldLand.cpp`, tests `EdLandTest.cpp`):
- `rotate = 1` on `perlin simplex ridged billow musgrave fbm_damped`: every octave in its own frame (a turn by the golden angle times the octave, a shift of the origin) and 64 evenly spread gradient directions. Default 0 so every old result and golden checksum stays bit identical (`EdFieldTest`, `EdT7Test`, `EdErosionTest` goldens unchanged; the 4 goldens of `EdFieldTest` and 10 of `EdT7Test` that differ when built with g++ on Linux are the same ones that differ at HEAD without this change: libm `pow` / `exp` / `atan2`). The graph nodes and presets pass `rotate = 1` (graphnodes.lua, graphnodes_t7.lua), so saved graphs change their noise (the editor is not in production).
- `fractal` (generator): gradient noise with `kind` fbm | billow | ridged (ridged multifractal: every octave weighted by the one before, `sharpness` = ridge exponent), `warp` (domain warp by a second noise; an octave moves by at most a quarter of its own wavelength, so fine octaves are not smeared), `slope_detail` (-1..1: finer octaves louder on steep (+) or flat (-) ground, from the analytic gradient of the coarser octaves), `finest` (smallest wavelength an octave may have, units), `persistence`, `lacunarity`, `rotate` (default 1). Output 0..1 with a soft limit (a clamp had cut flat discs into the highest peaks). Graph node `Terrain noise`.
- `amplitude`: zero-mean relief of an exact size (`mode` peak: largest rise or dip = amplitude; range; sd) - exact to float precision (tested).
- `terrain_mix`: mixes a relief into the terrain: `mode` add | multiply (higher ground gets more) | max (raise only) | min (lower only) | replace (mean + relief), `strength`, `mask`; where strength * mask is 0 the terrain is returned bit for bit.
- `keep_side`: water level clamp: dry ground is not dug under the water, the sea floor is not raised above it, only lowered dry / raised wet samples are touched and never past their old height.
**Lua** (`fieldgen.lua`, `gui/panels_fields.lua`, `selftest_fieldgen.lua`): presets Hills, Mountains, Badlands, Dunes, Plains detail, Rocks (op chains on `fractal`, `terrace`, `dunes`, `cells`; optional `gullies` = a short droplet erosion `erode_droplet` on the relief), Blend, Amplitude (units), Strength, Feature size, Detail, Warp, Gullies, Seed + Random seed, Mask (whole map / playable area / selected area, with a soft border), Keep flat areas (start positions, mass, hydrocarbon, with a radius and a soft skirt), Keep water level, a picture of the new terrain or of the change (red up, blue down) and the statistics (largest change, mean, share of the map that moves). `Apply to terrain` is ONE undo entry. The old `Commit to heights` of the field operations below it still replaces the heights of the whole map, but asks first (click twice).

## 17. Stratum recipes: smooth rules instead of noise blobs (2026-10-22)

**Complaint**: "the stratum recipes still produce incredibly ugly results" (screenshot: lime blotches on olive ground, dark outlines along the cliff foot, thin white streaks, flat white snow, hard edges everywhere). **Reproduced** with a lab: the real `recipes.lua` / `maskgen.lua` / `roledetect.lua` / `fields.lua` on lupa (Lua 5.1) with the real native ops (`libfld.so`), three synthetic terrains (320 x 320: a massif with spurs and a cliff band on rolling ground, a ridged mountain range, a coast with a bay, two hills and water), the eight layers painted in the representative colours of the Evergreen textures, hillshaded 315 / 40. Causes found in the old rules:
(1) the second grass layer (`PatchField`) was a noise thresholded +-0.04 around the 55th percentile: hard-edged blobs at 45% coverage (the lime camouflage); dirt the same (+-0.035); (2) rock / dark rock / high rock / snow multiplied their selection with a single scale noise (`Breakup`: smoothstep 0.05 .. 0.30), cutting holes and spots; (3) the cavity rule for dark rock was `curvature OR lowest quarter AND slope > 22`, so a thin concave line at the foot of every cliff became a contour outline, and the slope ramps were 4 to 8 degrees wide; (4) high rock started at the 62nd PERCENTILE of the land heights, which on a map that is mostly flat ground is the height of the plain: 51% of the massif map became high rock; sand without water was the lowest 6% of the land (22% of the flat ground); (5) `Above(snow line, soft 5% of the relief)` + `Slope(0, cliff - 4, 8)` gave flat white plateaus with hard borders; (6) two layers of a role at opacity 1 on the same cell (the self test now checks it, the old rules failed it).
**New rules** (all in `recipes.lua`, header and `Builders`): every selection is a product of WIDE RAMPS (height ramps 20 to 25% of the relief, slope ramps 15 to 25 degrees) and a blur of at least 3 units; noise never cuts: the `height` and `slope` rules of the mask generator got `wobble` (units or degrees), `wsize`, `wseed` (the field they read is moved by a fractal noise, so a threshold wobbles by a few percent of its range and the edge stays soft) and `height` got `sun` / `sunaz` (the band starts higher on the sun side: snow lies longer in the shade); noise kind 5 is the engine's `fractal` (rotated octaves). Dirt and the second grass are wide smoothsteps of fractal noise at partial opacity (dirt at most 0.9, variants at most 0.55), calibrated by `NoiseAt` so that Dirt coverage means that share. Rock = slope ramp from Rock slope (0) to Cliff slope (1); dark rock = concave ground on slopes, blurred 6 units, at most 0.15 + 0.4 x amount; high rock = altitude ramp from `high` x relief (relief = 3rd .. 99.5th percentile of the land), x (slope or convex or 0.3); snow = ramp around the snow line (the top share, with a floor so a flat map is not white) x (1 - cliff ramp), sun side shifted; sand only with water (a dry map only in the desert style: dry basins). Knob `high` is now a share of the HEIGHT RANGE (default 0.5); the dirt default is 0.38. The panel and the API are unchanged.
**Measured** (lab, 3 terrains x 6 styles, `scratchpad/rec2/metrics.py`; the visible weight of a layer = its mask x what the layers above leave free): width of the transitions (0.8 / gradient of the weight, cells with a weight between 0.1 and 0.9, ground below 25 degrees): the smallest median over roles and runs 4.4 cells (p10 2.1) before -> 5.7 (p10 4.2) now; one-cell lines (second difference above 0.3): up to 2.2% of the cells before -> 0; the largest change of a visible weight between two neighbouring cells is 0.12 .. 0.23 now. Share of ground below 12 degrees: grass 0.48 .. 0.91 (the low end the arctic and desert styles, the high end the mountain range, where little ground is flat), dirt 0.01 .. 0.34, sand 0.00 .. 0.37 (only the desert style on a dry map; before: sand 0.31 .. 0.66 on a dry map in every style). Share of the land: rock 0.05 .. 0.32 (before 0.00 .. 0.11: slopes were almost never rock), snow 0.01 .. 0.15 in the styles with default snow (arctic 0.14 .. 0.57 by design), high rock 0.05 .. 0.31 (before 0.26 .. 0.59), dark rock 0.02 .. 0.14 (before 0.00 .. 0.30). `selftest_recipes.lua` has two new checks (what a layer shows changes by at most 0.3 per cell, second difference at most 0.25: the old rules fail the second with 0.70, the new ones measure 0.12 / 0.08).
**Not verified**: the look in the game (the colours in the lab are flat averages of the textures, no normal maps, no shader blending); the Windows build of the native ops (the lab uses g++); preview of a role on maps above 700 samples (step 2) was not run.
